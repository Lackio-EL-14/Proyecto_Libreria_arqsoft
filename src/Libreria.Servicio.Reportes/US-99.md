# US-99 — Implementación simplificada

## Qué cambió

- Se eliminó `Application/UseCases/ExportExampleReportUseCase.cs`: solo reenviaba
  una llamada a ReporteFacade. El controlador de exportación ahora llama a la fachada.
- Se eliminó `Application/DTOs/PreparedReport.cs`: era un contenedor del documento
  y su PNG. Los generadores ahora reciben esos dos argumentos directamente.
- ReadExampleReportUseCase dejó de ser un intermediario. Ahora valida la identidad,
  consulta el repositorio y prepara el documento con usuario y fecha UTC.
- ReporteFacade coordina ese caso de uso, el gráfico y el creador PDF/Excel.
  Para dos formatos basta buscar el creador registrado; se retiró el diccionario.
- Se actualizaron las pruebas sin eliminar cobertura y se acortó este informe.

Se verificó que las clases retiradas no tuvieran consumidores fuera de Reportes.
No hay cambios en las rutas, solicitudes JSON ni respuestas de descarga. No se
implementaron filtros, reportes definitivos ni la plantilla de historias posteriores.

ScottPlot 5.1.59 (MIT). Ya estaban instaladas y verificadas en .NET 10; este ajuste
no cambia versiones ni agrega paquetes. PdfPig sigue siendo solo una dependencia
de pruebas para abrir y comprobar el PDF.

## Para la defensa

Explicar este recorrido: el controlador delega en Application; la fachada pide el
documento al caso de uso, genera el PNG y usa el creador del formato para exportar.
Factory Method es el método CreateGenerator sobrescrito por los creadores PDF y
Excel. Singleton guarda una sola configuración, no una conexión SQL compartida.
Las interfaces conservadas permiten sustituir SQL, HTTP o la librería de generación
sin introducir esas dependencias en el núcleo.

AGENTS.md y el cambio local de LoginValidator.cs se conservaron intactos. No se
cambió de rama ni se ejecutaron git add, commit, push, merge o rebase. La consulta
remota estuvo bloqueada por conexión; no se afirma que develop esté actualizado.
US-102, US-100 y US-101 no se iniciaron.
